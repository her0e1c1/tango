This is an operational inventory for retiring executable coverage, not a specification case index or proof of Playwright coverage. Keep the legacy test code and its existing CI execution until an executable replacement proves the same behavior.

## Contract IDs and retirement gate

- Each literal legacy ID below maps to the Playwright specification ID obtained by replacing only the `STORYBOOK-` prefix with `PLAYWRIGHT-`. Preserve the remaining name and number; shared IDs may occur in multiple files.
- The 206 unique legacy IDs remain the expected reference set for the screen integration implementation check. All must remain in integration stories; a component story with the same ID cannot substitute for a missing screen check. Their presence in legacy plays does not implement a Playwright case. The Playwright implementation check uses actual Playwright test sources independently.
- A legacy ID may leave this inventory only after the replacement Playwright test has executed successfully with the same Given / When / Then and all relevant input, language, focus, responsive, and asynchronous variants. Then retire only the covered legacy assertions and code, updating every affected inventory row and reference together. Matching an ID alone is insufficient.
- When an ID occurs in both a screen story and a component story, inspect the assertions and variants in both places. Shared IDs do not establish equivalent coverage.
- A play without a specification ID has the same retirement gate: first define and execute its equivalent Playwright contract. Do not silently drop it when removing the Storybook runner.
- The initial `PLAYWRIGHT-STUDY-SESSION-40` pilot is a separate contract. Its success verifies only that pilot; it retires **zero** of the 206 legacy contracts. The broader modifier-input contract remains pending until all of its expectations have executable coverage.
- Keep `npm run test:storybook`, the Vitest Storybook project, and the existing CI checks while any unretired legacy coverage remains. Keep the visual Storybook build and publication after the test migration as well.

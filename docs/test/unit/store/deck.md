# Deck Store 単体テスト仕様書

## 目的

取得済みデックの一覧が最新の結果に切り替わり、クリア後に以前のデックを参照できないことを確認する。書き込みの受付・成功・失敗と購読通知を分け、通知前には参照結果を直接変更しないことも確認する。Firestore の実際の保存・通信、document の検証、認証ライフサイクルは対象外とする。

関連 E2E: [CARD-LIST-ACTIONS-01](../../e2e/card-list-actions.md#card-list-actions-01)、[ACCOUNT-04](../../e2e/account.md#account-04)

共通の検証前提は [AGENTS.md](./AGENTS.md) を参照する。

### UNIT-STORE-DECK-01 [TODO] 最新の取得結果だけをデック一覧として提供する

カテゴリ: `state-change`

区分: 正常系

Given:

次の変更前のデックを保持している。各行を独立して検証する。

| 変更前のデック | 新しい取得結果 |
| --- | --- |
| なし | A、B |
| A（名前が旧名称）、B | A（名前が新名称）、C |
| A、B | なし |

When:

新しい取得結果をデックモデルへ反映する。

Then:

参照できるデックの ID と内容は新しい取得結果に一致する。以前だけ存在した B や A の旧名称は残らず、空の結果を受け取った場合は以前のデックを参照できない。

### UNIT-STORE-DECK-02 [TODO] デックのクリア後は以前のデックを参照できない

カテゴリ: `scope-reset`

区分: 正常系

Given:

デック A、B を保持している場合と、デックを保持していない場合を用意する。

When:

デックモデルのクリア操作を行う。

Then:

どちらの場合もデック一覧は空となり、以前のデックを参照できない。既に空であっても操作は失敗しない。

<a id="unit-store-deck-03"></a>

### UNIT-STORE-DECK-03 [TODO] デックの作成・編集・削除は書き込み完了ではなく購読通知で反映する

カテゴリ: `state-change`

区分: 正常系

Given:

本人のデックを購読している。対象外の B は名前・選択タグと絞り込み条件を標準値から変更済みである。各行を独立した状態とする。

| 操作 | 操作前 | 後から届く取得結果 |
| --- | --- | --- |
| A を作成 | B のみ | 指定した内容の A と既存の B |
| A を編集 | 変更前の A と B | 変更後の A と既存の B |
| A を削除 | 未削除の A と B | 削除日時が付いた A と既存の B |

When:

表の公開操作を行い、購読通知がまだない時点で操作の受付後と SDK の書き込み成功後の状態をそれぞれ参照する。その後、表の取得結果が購読へ届く。

Then:

購読通知前は、操作の受付後も書き込み成功後も参照結果が操作前と一致する。通知後は作成した A が現れ、編集した A の名前・選択タグと絞り込み条件が更新され、削除した A は参照できなくなる。すべての時点で B の ID と内容を維持し、A の重複や古い編集内容は残らない。これは通知前後の状態を保証し、保存の成功や SDK の通知生成自体は保証しない。

### UNIT-STORE-DECK-04 [TODO] デックの書き込み失敗だけでは直前の購読結果を変更しない

カテゴリ: `state-change`

区分: 異常系

Given:

本人の B を取得済みで、名前・選択タグと絞り込み条件を標準値から変更している。各行を独立して用意する。

| 操作 | 操作前の A | 失敗後の A |
| --- | --- | --- |
| 新規作成 | 存在しない | 存在しない |
| 編集 | B とは異なる変更済みの内容で取得済み | 操作前の内容のまま |
| 削除 | B とは異なる変更済みの内容で取得済み | 操作前の内容のまま |

When:

公開操作が受け付けられた後、SDK の書き込みが失敗する。新しい取得結果は届かない。

Then:

A の有無と内容は表に一致し、B の ID と名前・選択タグと絞り込み条件は操作前と一致する。作成対象の追加、編集内容への置き換え、削除対象の除外、一覧全体の消去を行わない。エラー表示や再試行はこのケースの対象外とする。

# Deck Store 単体テスト仕様書

## 目的

取得済みデックの一覧が最新の結果に切り替わり、クリア後に以前のデックを参照できないことを確認する。購読通知前後の一覧の変化と、購読エラー時に維持される内容も確認する。Firestore の実際の保存・通信、document の検証、認証ライフサイクルは対象外とする。

関連 E2E: [CARD-LIST-ACTIONS-01](../../e2e/card-list-actions.md#card-list-actions-01)、[ACCOUNT-04](../../e2e/account.md#account-04)

共通の検証前提は [AGENTS.md](./AGENTS.md) を参照する。

取得済みデータと同期位置の保存・復元は [差分同期](../../integration/firestore/incremental-sync.md) と [Persistence](../../e2e/persistence.md) で確認する。

### UNIT-STORE-DECK-01 [TODO] 最新の取得結果だけをデック一覧として提供する

カテゴリ: `state-change`

区分: 正常系

Given:

次の変更前のデックを保持している。各行を独立して検証する。

| 変更前のデック | 新しい取得結果 |
| --- | --- |
| なし | A、B |
| A（名前が旧名称）、B | A（名前が新名称）、C |
| A、B | なし |

When:

本人のデックの購読を開始した後、外部データソースから表の新しい取得結果が通知される。

Then:

公開 query で参照できるデックの ID と内容は新しい取得結果に一致する。以前だけ存在した B や A の旧名称は残らず、空の結果を受け取った場合は以前のデックを参照できない。

Then:

<a id="unit-store-deck-03"></a>

### UNIT-STORE-DECK-03 [TODO] 作成したデックは購読通知を受けて一覧に加わる

カテゴリ: `state-change`

区分: 正常系

Given:

本人のデックの購読を開始し、外部データソースからの通知でB だけを取得済みである。A は存在せず、B の名前・選択タグと絞り込み条件は標準値から変更済みである。

When:

A を作成する。変更後の取得結果がまだ通知されていない間の一覧を参照し、その後、外部データソースから作成した A と既存の B を含む取得結果が通知される。

Then:

通知前の公開 query の結果は B だけのままである。通知後は A と B がそれぞれ1件ずつ含まれ、A の内容は通知された値に一致する。すべての時点で、公開 query から取得できる B の ID と名前・選択タグと絞り込み条件は変わらない。

### UNIT-STORE-DECK-04 [TODO] 購読エラーでも取得済みのデック一覧を維持する

カテゴリ: `state-change`

区分: 異常系

Given:

本人のデックの購読を開始し、外部データソースからの通知でA と B を取得済みである。両者の名前・選択タグと絞り込み条件は異なる変更済みの値である。

When:

新しい取得結果の通知を受ける前に、外部データソースから購読エラーが通知される。

Then:

公開 query の結果は直前に取得した A と B の ID と名前・選択タグと絞り込み条件を保持し、空の一覧へ置き換わらない。利用側には購読の失敗が通知され、正常な取得完了としては扱われない。

### UNIT-STORE-DECK-05 [TODO] 編集したデックは購読通知を受けて内容が変わる

カテゴリ: `state-change`

区分: 正常系

Given:

本人のデックの購読を開始し、外部データソースからの通知でA と B を取得済みである。両者の名前・選択タグと絞り込み条件は異なる変更済みの値である。

When:

A の名前・選択タグと絞り込み条件を変更する。変更後の取得結果がまだ通知されていない間の一覧を参照し、その後、外部データソースから変更後の A と既存の B を含む取得結果が通知される。

Then:

通知前の公開 query の結果は変更前の A と B のままである。通知後は A の名前・選択タグと絞り込み条件が通知された値に変わり、同じ ID の古い内容や重複した A は残らない。すべての時点で、公開 query から取得できる B の ID と名前・選択タグと絞り込み条件は変わらない。

### UNIT-STORE-DECK-06 [TODO] 削除したデックは購読通知を受けて一覧から外れる

カテゴリ: `state-change`

区分: 正常系

Given:

本人のデックの購読を開始し、外部データソースからの通知でA と B を取得済みである。両者の名前・選択タグと絞り込み条件は異なる変更済みの値である。

When:

A を削除する。変更後の取得結果がまだ通知されていない間の一覧を参照し、その後、外部データソースから A が削除済みで B は変更されていない取得結果が通知される。

Then:

通知前の公開 query の結果には A と B が残る。通知後は B だけとなり、A は参照できない。すべての時点で、公開 query から取得できる B の ID と名前・選択タグと絞り込み条件は変わらない。

# Deck Store 単体テスト仕様書

## 目的

取得済みデックの一覧が最新の結果に切り替わり、クリア後に以前のデックを参照できないことを確認する。保存した変更を取得するまでの状態と、保存に失敗したときに維持される内容も確認する。Firestore の実際の保存・通信、document の検証、認証ライフサイクルは対象外とする。

関連 E2E: [CARD-LIST-ACTIONS-01](../../e2e/card-list-actions.md#card-list-actions-01)、[ACCOUNT-04](../../e2e/account.md#account-04)

共通の検証前提は [AGENTS.md](./AGENTS.md) を参照する。

### UNIT-STORE-DECK-01 [TODO] 最新の取得結果だけをデック一覧として提供する

カテゴリ: `state-change`

区分: 正常系

Given:

次の変更前のデックを保持している。各行を独立して検証する。

| 変更前のデック | 新しい取得結果 |
| --- | --- |
| なし | A、B |
| A（名前が旧名称）、B | A（名前が新名称）、C |
| A、B | なし |

When:

新しい取得結果をデックモデルへ反映する。

Then:

参照できるデックの ID と内容は新しい取得結果に一致する。以前だけ存在した B や A の旧名称は残らず、空の結果を受け取った場合は以前のデックを参照できない。

### UNIT-STORE-DECK-02 [TODO] デックのクリア後は以前のデックを参照できない

カテゴリ: `scope-reset`

区分: 正常系

Given:

デック A、B を保持している場合と、デックを保持していない場合を用意する。

When:

デックモデルのクリア操作を行う。

Then:

どちらの場合もデック一覧は空となり、以前のデックを参照できない。既に空であっても操作は失敗しない。

<a id="unit-store-deck-03"></a>

### UNIT-STORE-DECK-03 [TODO] デックの作成・編集・削除を最新の取得結果に合わせて反映する

カテゴリ: `state-change`

区分: 正常系

Given:

本人のデック一覧を取得済みである。対象外の B は名前・選択タグと絞り込み条件を標準値から変更済みである。各行を独立した状態とする。

| 操作 | 操作前の一覧 | 変更を取得した後の一覧 |
| --- | --- | --- |
| A を作成 | B のみ | 指定した内容の A と既存の B |
| A を編集 | 変更前の A と B | 変更後の A と既存の B |
| A を削除 | A と B | B のみ |

When:

表の操作を行う。操作が受け付けられ、保存が完了した後もしばらく変更後の一覧を取得できず、その後に最新の一覧を取得する。

Then:

変更後の一覧を取得するまでは、操作が受け付けられた後も保存が完了した後も一覧が操作前と一致する。取得後は作成した A が現れ、編集した A の名前・選択タグと絞り込み条件が更新され、削除した A は参照できなくなる。すべての時点で B の ID と内容を維持し、A の重複や古い編集内容は残らない。

### UNIT-STORE-DECK-04 [TODO] デックの保存に失敗しても取得済みのデックを維持する

カテゴリ: `state-change`

区分: 異常系

Given:

本人の B を取得済みで、名前・選択タグと絞り込み条件を標準値から変更している。各行を独立して用意する。

| 操作 | 操作前の A | 失敗後の A |
| --- | --- | --- |
| 新規作成 | 存在しない | 存在しない |
| 編集 | B とは異なる変更済みの内容で取得済み | 操作前の内容のまま |
| 削除 | B とは異なる変更済みの内容で取得済み | 操作前の内容のまま |

When:

指定した操作が受け付けられた後、その変更の保存に失敗する。変更後の内容は取得していない。

Then:

A の有無と内容は表に一致し、B の ID と名前・選択タグと絞り込み条件は操作前と一致する。作成対象の追加、編集内容への置き換え、削除対象の除外、一覧全体の消去を行わない。

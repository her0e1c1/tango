# Study Session Store 単体テスト仕様書

## 目的

デックごとの学習の続きを参照でき、削除・所有者変更・取得完了によって他のデックや利用者のセッションを混同しないことを確認する。書き込みと購読通知の間の再開対象、および購読開始・初回結果・エラー通知による取得待ちの遷移も確認する。カードの選定規則、FSRS、Firestore への実際の保存、認証に伴う購読の開始・停止は対象外とする。

関連 E2E: [STUDY-SESSION-01](../../e2e/study-session.md#study-session-01)、[STUDY-ACTIONS-04](../../e2e/study-actions.md#study-actions-04)、[ACCOUNT-04](../../e2e/account.md#account-04)

共通の検証前提は [AGENTS.md](./AGENTS.md) を参照する。

### UNIT-STORE-STUDY-01 [TODO] デックごとの学習の続きが互いに混ざらない

カテゴリ: `state-change`

区分: 正常系

Given:

同じ利用者に、デック A のセッション（カード順 a1、a2、学習の続きは 2 枚目）と、デック B のセッション（カード順 b1、学習の続きは 1 枚目）がある。両者のセッション識別子と最終学習時刻も異なる。

When:

両セッションを学習セッションモデルへ反映する。

Then:

デック A と B を指定した参照結果は、それぞれのセッション識別子、カード順、学習位置、最終学習時刻に一致する。互いの値を上書きせず、存在しないデック C のセッションは取得できない。

<a id="unit-store-study-02"></a>

### UNIT-STORE-STUDY-02 最新の取得結果にないデックを学習の続きから除外する

カテゴリ: `state-change`

区分: 正常系

Given:

デック A と B に、カード順・学習位置・最終学習時刻が異なるセッションを保持している。

When:

B のセッションだけを含む最新の取得結果を反映する。

Then:

A だけが取得できなくなり、B の識別子・カード順・学習位置・最終学習時刻は変更されない。

### UNIT-STORE-STUDY-03 [TODO] 学習中の情報をクリアしても旧バックアップを失わない

カテゴリ: `scope-reset`

区分: 正常系

Given:

複数デックのセッションを保持して取得待ちであり、以前の保存形式の学習バックアップがある。既にセッションがなく取得待ちでもない場合も独立して用意する。

When:

学習セッションモデルのクリア操作を行う。

Then:

どのデックのセッションも取得できず、取得待ちではなくなる。既に空でも操作は失敗しない。旧バックアップの内容は変更・削除されない。

### UNIT-STORE-STUDY-04 [TODO] 所有者を変更したら一致しない学習の続きを提供しない

カテゴリ: `scope-reset`

区分: 正常系

Given:

利用者 a のデック A と B のセッションを保持している。各行を独立して検証する。

| 新しい所有者 | 変更後に取得できるセッション | 取得待ち |
| --- | --- | --- |
| 利用者 a | A、B を変更せず維持 | はい |
| 利用者 b | なし | はい |
| 所有者なし | なし | いいえ |

When:

学習セッションモデルへ新しい所有者を通知する。

Then:

参照結果と取得待ちの有無は表に一致する。同じ所有者の再取得では学習位置などを失わず、別の所有者や所有者なしに変わった場合は以前の利用者の学習の続きを提供しない。

### UNIT-STORE-STUDY-05 [TODO] 最新の取得結果に学習の続きを切り替えて取得待ちを終了する

カテゴリ: `state-change`

区分: 正常系

Given:

同じ所有者のデック A、B のセッションを保持して取得待ちである。新しい取得結果として、次の各条件を独立して用意する。

| 新しい取得結果 | 取得できるセッション |
| --- | --- |
| A の更新された学習位置・最終学習時刻と C のセッション | 更新後の A と C のみ |
| セッションなし | なし |

When:

新しい取得結果を学習セッションモデルへ反映する。

Then:

参照結果は表に一致し、以前だけ存在したセッションや A の古い学習位置・最終学習時刻は残らない。結果が空の場合も取得待ちは終了する。

### UNIT-STORE-STUDY-06 [TODO] 取得待ちだけを終了すると保持済みの学習の続きは変わらない

カテゴリ: `state-change`

区分: 正常系

Given:

デック A、B のセッションを保持して取得待ちである。セッションを保持せず取得待ちである場合も独立して用意する。

When:

取得結果の差し替えを伴わない取得終了を学習セッションモデルへ通知する。

Then:

取得待ちは終了し、保持済みのセッション識別子、カード順、学習位置、最終学習時刻は変更されない。セッションがなければ、そのまま何も取得できない。取得結果を空として反映する操作とは区別する。

### UNIT-STORE-STUDY-07 [TODO] 学習の開始・やり直しは購読通知後に再開対象を切り替える

カテゴリ: `state-change`

区分: 正常系

Given:

本人の学習を購読している。デック A の再開対象がない場合と、カード順 a1、a2、a3 の 2 枚目にいる旧セッションがある場合を独立して用意する。別デック B には異なる識別子・カード順・学習位置・最終学習時刻のセッションがある。

When:

A の学習をカード順 a3、a1 で開始する。通知のない状態で操作の受付後と SDK の書き込み成功後を参照し、その後、新セッションと B を含む取得結果が届く。やり直しの場合は旧セッションが中断済みで、新セッションより古い作成日時を持つ。

Then:

通知前の A は、開始なら再開対象なし、やり直しなら旧セッションのままである。通知後に初めて、新しい識別子・指定したカード順・1 枚目の位置・通知された最終学習時刻を取得できる。B の識別子・カード順・学習位置・最終学習時刻は全時点で維持する。

### UNIT-STORE-STUDY-08 [TODO] 学習位置・再開時刻・終了状態は購読通知後に更新する

カテゴリ: `state-change`

区分: 正常系

Given:

本人のデック A と B の未終了セッションを取得済みである。両者の識別子・カード順・学習位置・最終学習時刻は異なる。各行を独立して用意する。

| 操作 | A の操作前 | 通知後の A |
| --- | --- | --- |
| 次へ進む | 3 枚中の 1 枚目 | 同じセッションの 2 枚目 |
| 後の位置を指定する | 3 枚中の 1 枚目 | 同じセッションの 3 枚目 |
| 再開時刻を記録する | 3 枚中の 2 枚目 | 同じ順序・位置で最終学習時刻だけが新しい |
| 最後のカードを完了する | 3 枚中の 3 枚目 | 再開対象なし |
| 明示的に中断する | 3 枚中の 2 枚目 | 再開対象なし |

When:

表の公開操作を行い、通知のない状態で操作の受付後と SDK の書き込み成功後を参照する。その後、操作に対応する位置・更新日時・終了状態を持つ A と、変更していない B の取得結果が届く。

Then:

通知前は A の識別子・カード順・学習位置・最終学習時刻が操作前と一致し、終了操作でも再開対象に残る。通知後は表の状態になり、未終了なら同じ識別子とカード順を保持し、最終学習時刻は通知された更新日時になる。B の内容は全時点で維持する。

### UNIT-STORE-STUDY-09 [TODO] 学習の書き込み失敗だけでは再開対象を変更しない

カテゴリ: `state-change`

区分: 異常系

Given:

本人のデック B にセッションがある。A の初回開始は再開対象がない状態から行う。A のやり直し、次への進行、後の位置の指定、中断、最後のカードの完了、再開時刻の記録は、B とは異なる識別子・カード順・学習位置・最終学習時刻のセッションがある有効な状態から、それぞれ独立して行う。

When:

公開操作が受け付けられた後、SDK の書き込みが失敗する。新しい取得結果は届かない。

Then:

初回開始では A の再開対象は存在しないままである。それ以外では A の再開対象は操作前の識別子・カード順・学習位置・最終学習時刻を保持する。どの場合も B の内容は変わらない。A を新しいセッションへ置き換えたり、位置を進めたり、再開対象から除外したりしない。再試行や保存先の復旧は対象外とする。

### UNIT-STORE-STUDY-10 [TODO] 学習の購読開始から初回通知まで取得待ちを維持する

カテゴリ: `state-change`

区分: 正常系

Given:

取得待ちではなく、利用者 a のデック A と B の学習を保持している。新たに購読する所有者は a または b とし、初回の結果はその所有者の有効なセッションがある場合と空の場合を独立して用意する。

When:

指定した所有者の購読を開始し、初回通知の前に再開対象と取得待ちを参照する。その後、初回の取得結果が届く。

Then:

通知前は取得待ちとなり、所有者が a なら A と B の内容を維持し、b なら a の学習は取得できない。通知後は初回結果に一致する再開対象となり、結果が空の場合も取得待ちが終了する。正常な取得完了の通知時点で、この状態を参照できる。認証変更による購読の切り替え全体は検証しない。

### UNIT-STORE-STUDY-11 [TODO] 学習の購読エラーで取得待ちを終了し保持済みの続きを維持する

カテゴリ: `state-change`

区分: 異常系

Given:

本人の学習の購読を開始して初回結果を待っている。同じ所有者の A と B のセッションを保持している場合と、保持済みのセッションがない場合を独立して用意する。A と B は識別子・カード順・学習位置・最終学習時刻が異なる。

When:

初回の取得結果が届く前に、購読からエラーが通知される。

Then:

取得待ちは終了し、エラーが利用側へ通知される。保持済みの A と B の内容は変わらず、保持済みのセッションがなければ再開対象なしのままである。エラー通知時点でこの状態を参照でき、正常な取得完了としては通知しない。実際の通信失敗や権限拒否の発生条件は保証しない。

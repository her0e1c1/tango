# Study Session Store 単体テスト仕様書

## 目的

デックごとの学習の続きを参照でき、削除・所有者変更・取得完了によって他のデックや利用者のセッションを混同しないことを確認する。保存した変更を取得するまでの再開対象、および学習の取得中・取得成功・取得失敗で変わる待機状態も確認する。カードの選定規則、FSRS、Firestore への実際の保存、認証に伴う購読の開始・停止は対象外とする。

関連 E2E: [STUDY-SESSION-01](../../e2e/study-session.md#study-session-01)、[STUDY-ACTIONS-04](../../e2e/study-actions.md#study-actions-04)、[ACCOUNT-04](../../e2e/account.md#account-04)

共通の検証前提は [AGENTS.md](./AGENTS.md) を参照する。

### UNIT-STORE-STUDY-01 [TODO] デックごとの学習の続きが互いに混ざらない

カテゴリ: `state-change`

区分: 正常系

Given:

同じ利用者に、デック A のセッション（カード順 a1、a2、学習の続きは 2 枚目）と、デック B のセッション（カード順 b1、学習の続きは 1 枚目）がある。両者のセッション識別子と最終学習時刻も異なる。

When:

両セッションを学習セッションモデルへ反映する。

Then:

デック A と B を指定した参照結果は、それぞれのセッション識別子、カード順、学習位置、最終学習時刻に一致する。互いの値を上書きせず、存在しないデック C のセッションは取得できない。

<a id="unit-store-study-02"></a>

### UNIT-STORE-STUDY-02 最新の取得結果にないデックを学習の続きから除外する

カテゴリ: `state-change`

区分: 正常系

Given:

デック A と B に、カード順・学習位置・最終学習時刻が異なるセッションを保持している。

When:

B のセッションだけを含む最新の取得結果を反映する。

Then:

A だけが取得できなくなり、B の識別子・カード順・学習位置・最終学習時刻は変更されない。

### UNIT-STORE-STUDY-03 [TODO] 学習中の情報をクリアしても旧バックアップを失わない

カテゴリ: `scope-reset`

区分: 正常系

Given:

複数デックのセッションを保持して取得待ちであり、以前の保存形式の学習バックアップがある。既にセッションがなく取得待ちでもない場合も独立して用意する。

When:

学習セッションモデルのクリア操作を行う。

Then:

どのデックのセッションも取得できず、取得待ちではなくなる。既に空でも操作は失敗しない。旧バックアップの内容は変更・削除されない。

### UNIT-STORE-STUDY-04 [TODO] 所有者を変更したら一致しない学習の続きを提供しない

カテゴリ: `scope-reset`

区分: 正常系

Given:

利用者 a のデック A と B のセッションを保持している。各行を独立して検証する。

| 新しい所有者 | 変更後に取得できるセッション | 取得待ち |
| --- | --- | --- |
| 利用者 a | A、B を変更せず維持 | はい |
| 利用者 b | なし | はい |
| 所有者なし | なし | いいえ |

When:

学習セッションモデルへ新しい所有者を通知する。

Then:

参照結果と取得待ちの有無は表に一致する。同じ所有者の再取得では学習位置などを失わず、別の所有者や所有者なしに変わった場合は以前の利用者の学習の続きを提供しない。

### UNIT-STORE-STUDY-05 [TODO] 最新の取得結果に学習の続きを切り替えて取得待ちを終了する

カテゴリ: `state-change`

区分: 正常系

Given:

同じ所有者のデック A、B のセッションを保持して取得待ちである。新しい取得結果として、次の各条件を独立して用意する。

| 新しい取得結果 | 取得できるセッション |
| --- | --- |
| A の更新された学習位置・最終学習時刻と C のセッション | 更新後の A と C のみ |
| セッションなし | なし |

When:

新しい取得結果を学習セッションモデルへ反映する。

Then:

参照結果は表に一致し、以前だけ存在したセッションや A の古い学習位置・最終学習時刻は残らない。結果が空の場合も取得待ちは終了する。

### UNIT-STORE-STUDY-06 [TODO] 取得待ちだけを終了すると保持済みの学習の続きは変わらない

カテゴリ: `state-change`

区分: 正常系

Given:

デック A、B のセッションを保持して取得待ちである。セッションを保持せず取得待ちである場合も独立して用意する。

Then:

### UNIT-STORE-STUDY-07 [TODO] 新しく始めた学習を取得するとその学習の続きから再開できる

カテゴリ: `state-change`

区分: 正常系

Given:

本人の学習の続きを取得済みである。デック A の再開対象がない場合と、カード順 a1、a2、a3 の 2 枚目にいる旧セッションがある場合を独立して用意する。別デック B には異なる識別子・カード順・学習位置・最終学習時刻のセッションがある。

When:

A の学習をカード順 a3、a1 で開始する。操作が受け付けられ、保存が完了した後もしばらく新しい学習を取得できず、その後に新しい学習の続きを取得する。やり直しの場合は以前の学習を中断して新しく始める。

Then:

新しい学習を取得するまでは、操作が受け付けられた後も保存が完了した後も、A は開始なら再開対象なし、やり直しなら以前の学習の続きのままである。取得後は、新しい識別子・カード順 a3、a1・1 枚目の位置となり、最終学習時刻は新しい学習の開始時刻になる。B の識別子・カード順・学習位置・最終学習時刻は全時点で維持する。

### UNIT-STORE-STUDY-08 [TODO] 取得した学習の進行・再開・終了に合わせて続きを更新する

カテゴリ: `state-change`

区分: 正常系

Given:

本人のデック A と B の未終了セッションを取得済みである。両者の識別子・カード順・学習位置・最終学習時刻は異なる。各行を独立して用意する。

| 操作 | A の操作前 | 変更を取得した後の A |
| --- | --- | --- |
| 次へ進む | 3 枚中の 1 枚目 | 同じセッションの 2 枚目 |
| 後の位置を指定する | 3 枚中の 1 枚目 | 同じセッションの 3 枚目 |
| 再開時刻を記録する | 3 枚中の 2 枚目 | 同じ順序・位置で最終学習時刻だけが新しい |
| 最後のカードを完了する | 3 枚中の 3 枚目 | 再開対象なし |
| 明示的に中断する | 3 枚中の 2 枚目 | 再開対象なし |

When:

表の操作を行う。操作が受け付けられ、保存が完了した後もしばらく変更後の学習を取得できず、その後に A の変更を含む最新の学習の続きを取得する。

Then:

変更後の学習を取得するまでは、操作が受け付けられた後も保存が完了した後も、A の識別子・カード順・学習位置・最終学習時刻が操作前と一致し、終了操作でも再開対象に残る。取得後は表の状態になり、未終了なら同じ識別子とカード順を保持し、最終学習時刻は取得した学習内容に一致する。B の内容は全時点で維持する。

### UNIT-STORE-STUDY-09 [TODO] 学習の保存に失敗しても取得済みの続きを維持する

カテゴリ: `state-change`

区分: 異常系

Given:

本人のデック B にセッションがある。A の初回開始は再開対象がない状態から行う。A のやり直し、次への進行、後の位置の指定、中断、最後のカードの完了、再開時刻の記録は、B とは異なる識別子・カード順・学習位置・最終学習時刻のセッションがある有効な状態から、それぞれ独立して行う。

When:

指定した操作が受け付けられた後、その変更の保存に失敗する。変更後の内容は取得していない。

Then:

初回開始では A の再開対象は存在しないままである。それ以外では A の再開対象は操作前の識別子・カード順・学習位置・最終学習時刻を保持する。どの場合も B の内容は変わらない。A を新しいセッションへ置き換えたり、位置を進めたり、再開対象から除外したりしない。

### UNIT-STORE-STUDY-10 [TODO] 学習の取得中は所有者に合う続きを保持し取得後に待機を終える

カテゴリ: `state-change`

区分: 正常系

Given:

取得待ちではなく、利用者 a のデック A と B の学習を保持している。次に学習を取得する所有者は a または b とし、その所有者に学習の続きがある場合とない場合を独立して用意する。

When:

指定した所有者の学習の取得を開始し、その後に取得を完了する。

Then:

取得中は取得待ちとなり、所有者が a なら A と B の内容を維持し、b なら a の学習は参照できない。取得完了後は、その所有者の最新の学習の続きだけを参照できる。学習の続きがない場合は再開対象がなくなり、どちらの場合も取得待ちが終了する。

### UNIT-STORE-STUDY-11 [TODO] 学習の取得に失敗したら待機を終えて取得済みの続きを維持する

カテゴリ: `state-change`

区分: 異常系

Given:

本人の学習を取得中であり、まだ結果は得られていない。同じ所有者の A と B のセッションを保持している場合と、保持済みのセッションがない場合を独立して用意する。A と B は識別子・カード順・学習位置・最終学習時刻が異なる。

When:

学習の取得に失敗する。

Then:

取得待ちは終了し、利用側は取得に失敗したことを把握できる。取得済みの A と B の識別子・カード順・学習位置・最終学習時刻は変わらず、取得済みの学習がなければ再開対象なしのままである。取得失敗を、学習がないという正常な取得結果として扱わない。

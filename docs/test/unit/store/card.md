# Card Store 単体テスト仕様書

## 目的

取得済みカードの変更と消去が参照結果に反映され、参照可能なデックに属する同じ所有者のカードだけを取得できることを確認する。購読通知前後の一覧の変化と、購読エラー時に維持される内容も確認する。Firestore document の検証、実際の保存・通信、購読の停止は扱わない。

関連 E2E: [CARD-VIEW-01](../../e2e/card-view.md#card-view-01)、[ACCOUNT-04](../../e2e/account.md#account-04)

共通の検証前提は [AGENTS.md](./AGENTS.md) を参照する。

### UNIT-STORE-CARD-01 [TODO] 最新の取得結果だけをカード一覧として提供する

カテゴリ: `state-change`

区分: 正常系

Given:

入力カードの所属デックと所有者は参照可能なデックと一致している。各行を独立して検証する。

| 変更前のカード | 新しい取得結果 |
| --- | --- |
| なし | A、B |
| A（表面が旧内容）、B | A（表面が新内容）、C |
| A、B | なし |

When:

本人のカードの購読を開始した後、外部データソースから表の新しい取得結果が通知される。

Then:

公開 query で参照できるカードの ID と内容は新しい取得結果に一致する。以前だけ存在した B や A の旧内容は残らず、空の結果を受け取った場合は以前のカードを参照できない。

### UNIT-STORE-CARD-02 [TODO] カードのクリア後は以前のカードを参照できない

カテゴリ: `scope-reset`

区分: 正常系

Given:

参照可能なデックに属するカード A、B を保持している場合と、カードを保持していない場合を用意する。

When:

カードモデルのクリア操作を行う。

Then:

どちらの場合もカード一覧は空となり、以前のカードを参照できない。既に空であっても操作は失敗しない。

### UNIT-STORE-CARD-03 [TODO] 所属デックと所有者が一致するカードだけを提供する

カテゴリ: `visibility`

区分: 正常系

Given:

カード A はデック X・利用者 a、カード B はデック X・利用者 b、カード C はデック Y・利用者 a に属する。カードを保持したまま、参照可能デックを次の各条件にする。

| 参照可能なデック | 取得できるカード |
| --- | --- |
| デック X・利用者 a | A のみ |
| デック X・利用者 b | B のみ |
| なし | なし |

When:

現在のカード一覧を取得する。

Then:

結果は表に一致する。デック ID だけが一致する別所有者のカードや、参照できるデックのないカードは含まれない。

<a id="unit-store-card-04"></a>

### UNIT-STORE-CARD-04 [TODO] 作成したカードは購読通知を受けて一覧に加わる

カテゴリ: `state-change`

区分: 正常系

Given:

本人のカードの購読を開始し、外部データソースからの通知でB だけを取得済みである。A は存在せず、B の表面・裏面の本文とタグは標準値から変更済みである。対象のカードはすべて本人の参照可能なデックに属する。

When:

A を作成する。変更後の取得結果がまだ通知されていない間の一覧を参照し、その後、外部データソースから作成した A と既存の B を含む取得結果が通知される。

Then:

通知前の公開 query の結果は B だけのままである。通知後は A と B がそれぞれ1件ずつ含まれ、A の内容は通知された値に一致する。すべての時点で、公開 query から取得できる B の ID と表面・裏面の本文とタグは変わらない。

### UNIT-STORE-CARD-05 [TODO] 購読エラーでも取得済みのカード一覧を維持する

カテゴリ: `state-change`

区分: 異常系

Given:

本人のカードの購読を開始し、外部データソースからの通知でA と B を取得済みである。両者の表面・裏面の本文とタグは異なる変更済みの値である。対象のカードはすべて本人の参照可能なデックに属する。

When:

新しい取得結果の通知を受ける前に、外部データソースから購読エラーが通知される。

Then:

公開 query の結果は直前に取得した A と B の ID と表面・裏面の本文とタグを保持し、空の一覧へ置き換わらない。利用側には購読の失敗が通知され、正常な取得完了としては扱われない。

### UNIT-STORE-CARD-06 [TODO] 編集したカードは購読通知を受けて内容が変わる

カテゴリ: `state-change`

区分: 正常系

Given:

本人のカードの購読を開始し、外部データソースからの通知でA と B を取得済みである。両者の表面・裏面の本文とタグは異なる変更済みの値である。対象のカードはすべて本人の参照可能なデックに属する。

When:

A の表面・裏面の本文とタグを変更する。変更後の取得結果がまだ通知されていない間の一覧を参照し、その後、外部データソースから変更後の A と既存の B を含む取得結果が通知される。

Then:

通知前の公開 query の結果は変更前の A と B のままである。通知後は A の表面・裏面の本文とタグが通知された値に変わり、同じ ID の古い内容や重複した A は残らない。すべての時点で、公開 query から取得できる B の ID と表面・裏面の本文とタグは変わらない。

### UNIT-STORE-CARD-07 [TODO] 削除したカードは購読通知を受けて一覧から外れる

カテゴリ: `state-change`

区分: 正常系

Given:

本人のカードの購読を開始し、外部データソースからの通知でA と B を取得済みである。両者の表面・裏面の本文とタグは異なる変更済みの値である。対象のカードはすべて本人の参照可能なデックに属する。

When:

A を削除する。変更後の取得結果がまだ通知されていない間の一覧を参照し、その後、外部データソースから A が削除済みで B は変更されていない取得結果が通知される。

Then:

通知前の公開 query の結果には A と B が残る。通知後は B だけとなり、A は参照できない。すべての時点で、公開 query から取得できる B の ID と表面・裏面の本文とタグは変わらない。

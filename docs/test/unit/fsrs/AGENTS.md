# FSRS 単体テスト仕様書の規約

## 対象

- Testing Trophy を前提に、評価による状態更新・復習期限の判定・想起確率の計算だけを扱う。関数数や分岐数に合わせてケースを増やさない。
- 観測境界は Card の FSRS ドメイン操作とする。状態・評価・時刻を入力し、返される状態・判定・確率、または入力拒否を検証する。
- Firestore・browser storage への保存、購読、権限、UI、出題順・件数・タイマーは対象外とし、各結合テストまたは E2E に委ねる。
- private helper、内部オブジェクト、依存関数の呼出回数・順序、ライブラリの全計算式を検証対象にしない。FSRS 自体の再実装は作らない。

## 記述と対応付け

- 仕様書は目的、ケース一覧、明示的なアンカー、ID 付き見出し、カテゴリ、区分、Given / When / Then、対応テストを持つ。区分は [共通規約](../../AGENTS.md#正常系異常系の区分) に従う。
- ID は `UNIT-FSRS-<大文字のファイル名>-<NN>` とし、各ファイルで `01` から欠番なく採番する。
- 一つのケースは一つの振る舞いとする。表の各行は独立した入力例であり、When では一回の評価・判定・計算を行う。事前の学習履歴は Given で準備する。
- ケースとテスト関数の 1:1 対応は要求しない。新規・変更する FSRS テストのタイトル先頭に該当 ID を付け、追加の振る舞いは先に仕様書へ記述する。
- `既存対応` は必要な assertion が既存コードにあること、`一部対応` は不足する assertion があること、`未対応` は対応する assertion がないことを表す。いずれもテスト実行の成功報告ではない。
- 未対応の期待結果を既存テストが保証していると記述しない。仕様書作成だけを理由にテストコードや実装を変更しない。

## 共通前提

- 採用版は `package.json` で固定する `ts-fsrs@5.4.2` / FSRS-6 とする。目標保持率 `0.9`、ランダムな間隔調整なし、最大間隔 `36,500` 日、短期学習あり、学習ステップ `1分・10分`、再学習ステップ `10分` を前提にする。
- 互換性の期待値は、この採用版と設定を独立に与えた参照計算から得る。テスト対象の出力や内部変換関数を期待値の生成に使わない。固定数値を使う場合は参照計算で確認した値だけを用いる。
- 基準時刻 `t0` は `2026-09-22T00:00:00.000Z` とし、時刻は Unix ミリ秒、経過時間の 1 日は `86,400,000` ミリ秒とする。実行日の現在時刻やローカル日付境界に依存させない。
- 特記のない評価済み状態は `review`、最終評価 `t0`、期限 `t0 + 10日`、安定性 `10` 日、難易度 `5`、評価回数 `3`、忘却回数 `1`、予定間隔 `10` 日、学習ステップ位置 `0` とする。各ケースはこの状態から明示した入力だけを変更する。
- `fsrs: null` だけが未評価を意味する。不正・欠落した状態を未評価や既定値に補正しない。エラーの具体的なクラス名や文言は固定しない。
- カテゴリ `write` は更新後の FSRS 状態を算出する契約を表し、保存の保証ではない。入力の学習状態は変更せず、同じ状態・評価・時刻には同じ結果を返す。
- 数値の時刻・回数・状態は正確に比較する。安定性・難易度・確率の参照計算との比較には絶対誤差 `1e-8` を許容する。確率は表示用の百分率に丸める前の値で検証する。

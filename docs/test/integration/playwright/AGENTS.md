# Playwright 画面結合テスト仕様書の記述規約

## 検証境界

- このディレクトリは、Firestore に接続せず、実際のアプリケーションの store に準備した状態から Playwright で操作する結合テストの仕様とする。
- 通常は `src/pages` の画面名に対応する一画面一ファイルとし、作成・編集・一覧・閲覧・学習開始・学習を分ける。起動・認証ゲート・共通復旧など App 境界から始める契約は `application.md` に置く。
- 実際の Page、model/action、フォーム、子コンポーネント、store、i18n、アプリ CSS を結合する。遷移は実際の router と遷移先の表示、通知は実際の通知領域で確認する。Page、検証対象の model/action、store を mock して結果を作らない。
- 認証・通信・保存・ファイル読み取りなど、検証対象の外にある I/O だけをテスト側で成功・失敗・待機に差し替える。画面内の CSV 解析、入力検証、選別、状態遷移は置き換えない。本番インターフェースをテスト専用に拡張しない。
- 部品単体の描画や callback の呼び出しだけでは、画面の結合テストを満たさない。画面から操作し、その操作で利用者が確認できる表示・選択・フォーカス・操作可否・遷移先、または公開された保存境界に渡る内容を確認する。
- 実際の Firestore の読み書き・購読・Rules は `../firestore`、ブラウザーの永続 cache・再読み込み・再接続・独立したブラウザー間の同期と利用者導線は `../../e2e` に置く。I/O の成功応答や状態更新を、サーバーへの実保存や再読み込み後の復元の証拠としない。

## 書式と ID

- [共通規約](../../AGENTS.md) のテンプレートに従い、目的、仕様書内のケース一覧、ID の anchor と見出し、カテゴリ、区分、日本語の Given / When / Then を記述する。ケース一覧の README や実装ファイル・テスト名の対応表を加えない。
- ID は `PLAYWRIGHT-<大文字の画面名>-<NN>` とし、anchor は ID の小文字とする。移設した契約では接頭辞以外の ID、旧部品名と欠番を維持する。新規ケースは対象の画面名の最大番号の次から採番する。
- Given は画面、利用可能なデータ、認証状態、設定、外部処理の結果を明示する。When は操作または外部からの事象、Then はその境界で確認できる結果とする。
- 表示を確認するケースは `render`、操作や入力に伴う結果は `interaction` とする。正常系・異常系はカテゴリとは別に記述する。
- 見出しの `[TODO]` は Playwright で Given / When / Then 全体を確認する実装がない、または一部が未検証であることを示す。部分的な pilot や別 runner の成功を理由に外さない。独立した狭い契約を先に実装する場合は別 ID にし、元の契約を狭めない。
- 実装した Playwright テストのタイトルまたは `test.step` の先頭に仕様 ID を置く。ID の存在や `[TODO]` がないことだけで、実行成功・網羅性・旧テストとの同等性を保証しない。

## 状態準備と共通確認

- 認証、Deck、Card、設定、学習、履歴は、実際の store に表示前に準備する。固定の ID・日時・判定時刻を使い、言語、共有状態、入力、選択、保存先の観測履歴、スクロール位置を実行単位で分離する。
- 復習期限を確認するケースは復習状態と判定時刻を準備し、未学習 Card だけで代替しない。通常の再描画で状態を初期化し直さない。
- 外部処理の結果は表示や公開境界への反映を待って確認する。固定時間の待機だけで成功としない。失敗時は必要な入力の保持、安全な案内、再試行できる状態を確認する。
- 操作は読み上げ名で特定し、契約に応じてキーボード到達、モーダルのフォーカス、ヘッダーと本文の重なりを確認する。狭い画面では viewport を固定する。
- 正常系では未処理の page error や予期しない console error がないことを確認する。異常系では想定した失敗が画面で処理され、それ以外の browser error を残さない。診断を保持する契約は許容する診断をケースに明記する。

## 実行と移行中の回帰テスト

- Playwright の実装は `test/integration/playwright` に置き、既存の標準 runner を使って `npm run test:playwright` で実行する。`npm run lint:test-specs` と `npm run lint:markdown` で参照・形式を確認する。参照 lint の成功を browser 実行の成功としない。
- Storybook のテスト仕様書は廃止し、このディレクトリの Playwright 契約へ移設した。旧 Storybook の実行コードは、固有の回帰検証を失わないための移行中のテストとして残る。旧 runner の成功は Playwright の実装済み・合格を意味しない。
- 旧実行コードの削除は、対象契約の Playwright での実行と同等な観測を確認した後に限る。未実施の退役は後続作業として明示し、表示・ドキュメント用の Storybook 機能はこの移行を理由に削除しない。

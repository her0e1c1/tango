# 匿名利用とアカウント同期を同じ Firestore 永続キャッシュで扱う

Status: Accepted

[ローカルとリモートの保存先を分ける決定](./20260908-separate-local-and-remote-persistence-identities.md)を置き換える。

## Decision

Deck・Card・StudySession・StudyAnswer は、匿名利用でも認証 UID と同じ Firestore API・永続キャッシュを使う。Deck ごとの保存先選択と、別系統のローカル CRUD は持たない。

- 匿名利用では Firestore のネットワークを無効にし、データを端末内に保持する。連携済みアカウントではネットワークを有効にして同期する。匿名認証の確立まで完全オフラインで行えるという保証ではない。
- 操作完了は SDK のローカル snapshot への反映で判断し、サーバーへの保存完了と区別する。未送信の書き込みと再接続後の同期は SDK に任せ、独自の送信待ちキューや二重の保存経路は作らない。
- UID が変わるときは旧所有者の購読と状態を切り離す。連携済みアカウントに未同期の書き込みがある間は、サインアウトを拒否する。
- 旧方式のブラウザーデータを自動移行する経路は残さない。

## Context

保存先ごとに CRUD・学習処理・移行処理を分けると、同じ操作でも完了条件や再試行が異なる。同じキャッシュと書き込み経路を使い、匿名利用と同期利用の差を認証に応じたネットワーク制御へ集約する。

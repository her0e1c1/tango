# 必要な検証がそろった場合だけ Test を成功にする

Status: Accepted

## Decision

ブランチ保護が参照するチェック名を `Test` に固定し、最後の集約ジョブで必要な検証結果を確認する。ジョブ構成とイベントごとの対象は共通の Test ワークフローに記述し、この文書には重複して列挙しない。

集約ジョブは依存ジョブの成否にかかわらず実行する。失敗・キャンセル・想定外のスキップが一つでもあれば失敗とし、イベントと変更内容から対象外と判定されたジョブだけ、明示した条件でスキップを許可する。

キャンセルするのは同じ PR の古い実行だけとし、手動実行と再利用ワークフローの呼び出し元は分離する。個別の検証ジョブは、原因調査と再利用のため独立させておく。

PR・push の変更検出は `dorny/paths-filter` に任せる。`.ts` / `.tsx` の変更時に build・実行テスト・完全なコード検査を行い、それ以外は Markdown と仕様参照の簡易チェックにする。手動実行など変更検出の対象外の呼び出しは完全な検査を行い、Dependency Review は TypeScript の変更有無によらず PR ごとに行う。

この条件では、依存関係・Rules・YAML・fixture だけの変更でも実行テストを省略する。必要な場合は手動で完全な Test を実行し、簡易チェックの成功を実行テストの合格と解釈しない。

## Context

ブランチ保護が多数のジョブ名に依存すると、分割や改名に弱くなる。不完全な検証を成功と扱うと、必要な確認なしにマージできてしまう。

文書更新のたびに全テストを実行する負担を減らす一方、対象外にした検査と失敗した検査を集約ジョブで区別する。
